# Validation Task Generation Reference Library

> **Status:** Reference asset; not an authoritative record of accepted AutoAdapter design decisions.
>
> **Purpose:** Provide per-morphology runtime surfaces, candidate driver surfaces, and original validation examples to the private validation-task generation process.
>
> **Boundary:** The entries and numeric thresholds below are source references. Storing them here does not make them the final validation tasks, oracle definitions, pass thresholds, Demo tasks, or held-out evaluation set. Accepted project decisions remain exclusively in `ROBOT_CAPABILITY_PRIMITIVES_RESEARCH_MAP.md`.
>
> **Provenance:** Imported from the user-provided task-generation reference table on 2026-08-04.

## Per-Morphology Surfaces and Original Validation

| Morphology                 | Runtime adapter to write                                                                                                                                                                                                                                                                                  | From-scratch or benchmark driver to write                                                                                                                                                                      | Original validation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Serial arm with gripper    | `joint_arm_v1`: `connect`, `read_joints`, `send_joints`, `open_gripper`, `close_gripper`, `stop`, `close`; conditional `read_camera` for D405 routes; route-defined `home`, `get_ee_pose`, `move_cartesian`, `move_relative_cartesian_bounded` where enabled. Applies to `soarm101`, `piper`, `franka`.   | Common driver methods plus `get_ee_pose`, `move_cartesian`; if gripper exists, `gripper_open`, `gripper_close`, `is_holding`; for manipulation scenes, `get_object_names`, `get_object_position`.              | `orchestrator.py`: skeleton `driver.py` must build; arm validation runs `home_settle`, `ik_roundtrip` with target `ee0 + [0.03, 0, 0.03]` and error `< 0.02 m`, `gripper_cycle`, and `grasp_lift` when weld-graspable bodies exist, requiring lift `> 0.05 m` and object-to-EE gap `< 0.12 m`. `orchestrator_from_scratch.py`: bans skeleton imports, builds `Robot`, runs `home`, `ik_roundtrip` with error `< 0.03 m`, `gripper_cycle`, `object_perception`, and `grasp_lift` requiring object rise `> 0.03 m` and object-to-EE gap `< 0.10 m`. |
| Serial arm without gripper | Same `joint_arm_v1` base contract, but gripper methods should be explicit no-op or unsupported signals rather than fake grasps. Applies to `ur5e`, `kuka_iiwa14`.                                                                                                                                         | Same arm driver core: common methods, `get_ee_pose`, `move_cartesian`; gripper helpers may be no-op/unsupported when no hardware is present.                                                                   | Same arm validation path. The original skeleton validator skips `gripper_cycle` when no gripper actuator exists and only runs `grasp_lift` when weld-graspable bodies exist. The from-scratch validator still requires arm class detection by `get_ee_pose` plus `move_cartesian`; object APIs are required and must return an empty list only when the scene truly has no movable objects.                                                                                                                                                       |
| Quadruped                  | Usually `quadruped_high_level_v1`: `connect`, `read_state`, `stand`, `sit`, `command_velocity`, `stop`, `close`. Applies to `go2`, `unitree_a1`. `anymal_c` uses `mission_api_v1`: `connect`, `read_state`, `start_mission`, `stop_mission`, `stop`, `close`, because its runtime route is mission-level. | Common driver methods plus `stand_up`, `sit`, `walk_forward`, `get_base_pose`, `get_body_height`. The driver may contain PD control and gait logic in MuJoCo.                                                  | `orchestrator.py`: skeleton `QuadrupedPDGaitSkeleton` validation runs `stand_up` with final body height `> 0.15 m`, `sit` with final height `< body_height_target * 0.7`, and `walk_forward` as a no-crash smoke with displacement reported. `orchestrator_from_scratch.py`: stricter physics validation, `stand_up` must end above `0.15 m` without collapse, `sit` must lower below `0.8 * standing_height`, and `walk_forward` must move forward `> 0.03 m` while body height stays `> 0.12 m`.                                                |
| Wheeled / mobile base      | Canonical runtime contract is `mobile_manipulator_v1` for `stretch3`: `connect`, `read_state`, `send_joints`, `command_base_velocity`, `open_gripper`, `close_gripper`, `stop`, `close`.                                                                                                                  | Common driver methods plus `drive_forward`, `turn`, `get_base_pose`, `get_base_yaw`. For `stretch3` as a mobile manipulator, the benchmark sets also include arm driver requirements when the arm is in scope. | Only `orchestrator_from_scratch.py` has morphology-specific validation: class is detected by `drive_forward` plus `turn`; `drive_forward(distance_m=0.3)` must create horizontal displacement `> 0.05 m`; `turn(0.785)` must change yaw by `> 0.2 rad`. The original skeleton `orchestrator.py` has no wheeled skeleton validator and would only do introspection for unknown skeleton classes.                                                                                                                                                   |
| Aerial / multirotor        | Runtime is `mission_api_v1` for `skydio_x2`: `connect`, `read_state`, `start_mission`, `stop_mission`, `stop`, `close`; do not expose raw rotor or thrust control through runtime adapters.                                                                                                               | Common driver methods plus `takeoff`, `move_to`, `hover`, `get_base_pose`, `land`. The from-scratch driver must implement closed-loop flight control in MuJoCo.                                                | Only `orchestrator_from_scratch.py` has morphology-specific validation: class is detected by `takeoff` plus `move_to`; `takeoff(height=0.5)` must gain altitude by `> 0.15 m` and stay upright with body z-axis score `> 0.7`; `move_to` to a target about `+0.3 m` in X must end with error `< 0.25 m` and upright score `> 0.7`.                                                                                                                                                                                                                |
| Humanoid / biped           | `humanoid_high_level_v1`: `connect`, `read_state`, `stand`, `sit`, `command_velocity`, `stop`, `close`. Applies to `h1`; raw joint torque is rejected by default.                                                                                                                                         | Common driver methods plus `stand_balance`, `squat`, `get_base_pose`, `get_torso_height`; `walk_forward` is frontier/non-critical.                                                                             | Only `orchestrator_from_scratch.py` has morphology-specific validation: class is detected by `stand_balance` plus `squat`; `stand_balance(secs=2.0)` must keep torso height `> 0.6 m` and upright score `> 0.7`; `squat(depth=0.15)` must dip by at least `0.05 m`, recover above `0.6 m`, and stay upright `> 0.7`. Optional `walk_forward` is reported as `humanoid_walk`, but it is not part of `structural_ok`.                                                                                                                               |
