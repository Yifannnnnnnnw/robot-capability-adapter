THE METHOD

Build the interface.
Verify the behaviour.

A planner can compose tools, but a new robot still needs its own implementation. AutoAdapter brings that robot-specific software into the generation loop.

  1. 01 / DESIGN

    Define capabilities

    Turn robot descriptions and target tasks into reusable operations and measurable behavioural requirements.

    Robot information → interface & tests
  2. 02 / GENERATE

    Synthesise a driver

    Implement those operations in Python, using the robot's actual joints, actuators and observations.

    Capability interface → driver
  3. 03 / VALIDATE

    Observe and repair

    An independent Harness reads MuJoCo state, applies fixed criteria and provides feedback for driver repair.

    Physical state → verdict & feedback
  4. 04 / USE

    Compose operations

    ReCAP calls the generated capabilities to perform downstream tasks, whose outcomes are evaluated separately.

    Reusable operations → tasks
Why independent checks?

Executable code can still produce the wrong movement. The Harness judges simulator observations outside the candidate driver's control. Capability specifications and tests are still authored during Design.

ACROSS ROBOTS

Different bodies.
Different failure modes.

The thesis studies a fixed-base arm, a dexterous hand and an aerial robot. Accurate local movement does not automatically establish reliable contact or task completion.

CASE / 01

Franka Panda

From end-effector motion to tabletop manipulation.

ReCAP combines positioning, waypoints, gripper aperture and wrist rotation for drawer opening, dial turning and pick-and-place.

What this examinesReusing one driver across tasks with different motion and contact requirements.

CASE / 02

LEAP Hand

Positioning a fingertip is only the beginning.

Cases cover fingertip reach, joint pose, object holding, block manipulation and valve turning. Accurate local positioning did not translate into reliable object manipulation.

Observed limitationWhole-hand coordination, sustained contact and stability remain demanding.

CASE / 03

Skydio X2

Connecting generated operations to flight tasks.

The aerial robot case examines flight control, task interpretation and execution conditions, including failures and subsequent retries.

What this examinesHow task definitions and robot-specific preparation affect downstream outcomes.

These are selected simulation case studies, with robot-specific preparation and retries where documented. They are not a controlled morphology comparison or evidence of physical-hardware performance.
