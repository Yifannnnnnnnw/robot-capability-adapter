\title{Auto-Adapter: Robot-Specific Driver Synthesis with Independent Closed-Loop Validation}
\author{Yifan Wang}
\department{Department of Computer Science}

\maketitle
\makedeclaration

\begin{abstract}
This thesis investigates how task-level decisions in embodied-AI systems can
be translated into executable commands across different robots. It develops
and evaluates Auto-Adapter, which generates the required robot-specific drivers
and independently validates their behaviour before they are used for task
execution.
Auto-Adapter reads a robot description and a collection of target tasks,
proposes a small set of reusable robot operations, and generates the code that
exposes them to an agent. The proposed operations are evaluated against
measurable criteria in simulation, using observations and verdicts that remain
separate from the generated code. When a driver fails, Auto-Adapter permits a
fixed number of revision attempts. The study therefore distinguishes between
designing robot tools, implementing them, validating their behaviour, and
using them to complete tasks. The study evaluates seven LLMs across eleven
robot configurations. In the SO-101 diagnostic, the strongest generated driver
passed 14 of 18 independently evaluated cases (77.8\%).

The evaluation comprises three experiments.
\textbf{Experiment 1---Auto-Adapter Framework.}\\
The first experiment evaluates
the complete framework, from designing reusable robot operations to generating
and independently validating a robot-specific driver. Its purpose is to
determine whether Auto-Adapter can construct the robot-facing software required
by a tool-using agent.

\textbf{Experiment 2---AutoAdapter-Bench.} The benchmark evaluates LLMs
separately as creators and users of robot tools. Its purpose is to compare these
abilities and establish whether successful tool use also indicates successful
tool synthesis.

\textbf{Experiment 3---Cross-Robot Evaluation.} The final experiment applies
Auto-Adapter across different robot configurations. Its purpose is to analyse
how observed performance differs between robots and identify where the
framework succeeds or fails.


Within the evaluated scope, the thesis makes three scientific contributions:
\vspace{-\parskip}
\begin{enumerate}[leftmargin=*,labelsep=.8em,nosep]

  \item \textbf{Deriving Reusable Robot Operations from Tasks.}
  Auto-Adapter contributes a task-grounded design method that
  derives a task-neutral capability interface and measurable pass criteria from
  source-backed target tasks, without requiring a pre-authored capability
  catalogue or task-to-capability mapping.

  \item \textbf{Evaluating LLM-Generated Robot Drivers.}
  The framework makes robot-specific driver synthesis the
  evaluated research object. An LLM must implement the fixed capability contract
  through actuator-mediated Direct-MuJoCo control, with bounded Repair and at
  most three submitted drivers.

  \item \textbf{Validating Robot Behaviour Independently of Generated Code.}
  Implementation-blind validation prevents candidate code from
  choosing its private cases, measurements, physical-integrity checks, or final
  verdict, distinguishing interface conformance and model self-report from
  observed robot behaviour.

\end{enumerate}

The thesis also makes three bounded,
industry-relevant contributions:
\vspace{-\parskip}
\begin{enumerate}[leftmargin=*,labelsep=.8em,nosep]

  \item \textbf{Creating Versioned Robot Integration Packages.}
  A versioned robot integration package combines each robot's
  MuJoCo model, source-backed tasks, capability design, private validation
  bindings, and execution policy, supporting configuration-specific evaluation
  through a common experimental route.

  \item \textbf{Comparing LLMs under Fixed Conditions.}
  Fixed-input benchmarking holds each robot's capability
  interface, private validation suite, Harness, and resource budget constant
  while LLM backbones and generation conditions vary, with validation, Repair,
  failure, token, cost, and time outcomes reported separately.

  \item \textbf{Resource-Accounted Evaluation.}
  The evaluation reports behavioural outcomes alongside model calls, token use,
  cost, wall-clock time, revision history, and failure class. This supports
  practical trade-off analysis within the evaluated conditions without implying
  a universal model ranking.

\end{enumerate}

\end{abstract}
