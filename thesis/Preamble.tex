\title{Auto-Adapter: Robot-Specific Capability-Set Synthesis and Autonomous Closed-Loop Qualification}
\author{Yifan Wang}
\department{Department of Computer Science}

\maketitle
\makedeclaration

\begin{abstract}
Tool-using large language model (LLM) agents require a robot-specific
software interface that converts requested actions into simulator or
controller commands. Implementing this interface manually delays deployment
on every new robot and execution route. Auto-Adapter 1.0 showed that an LLM
could generate this layer from machine-readable robot descriptions: across
eight simulated robots, it produced structurally validated, smoke-tested
drivers at US\$\(2.98 \pm 0.84\) and \(7.8 \pm 1.6\) minutes per robot. Yet
all seven evaluated models could use a synthesised interface, while only three
generated a driver that passed validation.

Auto-Adapter 2.0 asks whether the model can also design the reusable capability
interface and its acceptance tests. Given public robot facts and at least
twenty tasks with documented pass conditions drawn from public sources, an LLM
defines five to ten reusable robot operations and validation criteria
traceable to those sources. It then generates a robot-specific driver either
with access to a trusted controller skeleton or from the required interface
alone. A separate harness controls MuJoCo actuators and advances physics
directly, applies hidden behavioural criteria that the generated code cannot
modify, and permits bounded repair from structured failures.

The evaluation comprises three experiments.
\textbf{Experiment 1---LLM backbone comparison.} We compare LLM backbones
when \textbf{synthesising} a reusable robot capability layer with a provided
controller skeleton or from scratch, and when \textbf{using} the same fixed,
validated capability layer with the same high-level controllers to complete
matched physical tasks.

\textbf{Experiment 2---Auto-Adapter framework analysis.} We analyse three
components of the framework.
\textbf{(a) Task-grounded capability design.} We test whether an LLM can
derive reusable capabilities from at least twenty source-backed tasks.
\textbf{(b) Capability-level pass-criteria design.} We test whether
source-grounded capability-level pass criteria can be generated without human
predefinition.
\textbf{(c) Continued Evolution.} We test whether reviewed evidence from
completed runs improves synthesis quality in later runs.

\textbf{Experiment 3---Cross-morphology analysis.} We hold the LLM backbone,
high-level controller, Auto-Adapter configuration, evaluation protocol, and
resource budget fixed while comparing low-level motion-control skill synthesis
across \textbf{different robot morphologies}.

Within the evaluated scope, the thesis makes three scientific contributions:
\vspace{-.65\baselineskip}
\begin{enumerate}[leftmargin=*,labelsep=.8em,nosep]

  \item AutoAdapter-Bench separates capability-layer \textbf{synthesis} from
  \textbf{use}. It evaluates the same LLM backbones in separate tracks and
  treats the two outcomes as different evidence categories, without assuming
  that they are statistically independent.

  \item Auto-Adapter makes capability and pass-criteria \textbf{design} part of
  capability-layer synthesis. The LLM derives both from source-backed tasks and
  reviewed task-level standards, while independent components control
  validation and Repair remains separate from later-run Evolution. A generated
  or successfully compiled criterion is not treated as reliable without the
  declared validation evidence.

  \item A controlled \textbf{cross-morphology} analysis studies low-level
  motion-control capability synthesis across the declared robot cohort. It
  compares validation outcomes, failure patterns, and resource use under
  matched conditions, and reports the observed differences as associations
  rather than causal morphology effects.

\end{enumerate}

Within the declared Direct-MuJoCo scope, the thesis also makes three bounded,
industry-relevant contributions:
\vspace{-.65\baselineskip}
\begin{enumerate}[leftmargin=*,labelsep=.8em,nosep]

  \item \textbf{Traceability} links reviewed task-level standards to
  model-authored capability-level pass criteria, independent compilation, and
  Harness verdicts for the declared tasks and validation cases.

  \item A repeatable robot \textbf{integration} package supports scoped
  \textbf{reuse}. It records the robot assets, control facts, source-backed
  tasks, validation inputs, capability interfaces, and generated driver needed
  to reproduce the declared integration.

  \item Comparable \textbf{evidence} supports failure \textbf{diagnosis}.
  AutoAdapter-Bench records synthesis and use separately, together with the
  LLM backbone, robot configuration, generation condition, outcomes, failure
  patterns, resource use, and per-trial evidence under matched conditions.

\end{enumerate}

These contributions are limited to the declared tasks, robot configurations,
generation conditions, and Direct-MuJoCo evaluation protocol. They do not
establish standards compliance, industrial certification, real-SDK fidelity,
hardware safety, sim-to-real transfer, reduced integration time, production
reliability, universal LLM superiority, or a causal morphology effect.
\end{abstract}
