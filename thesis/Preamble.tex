\title{Auto-Adapter: Robot-Specific Driver Synthesis with Independent Closed-Loop Validation}
\author{Yifan Wang}
\department{Department of Computer Science}

\maketitle
\makedeclaration

\begin{abstract}
Tool-using large language model (LLM) agents require a reusable robot capability
interface through which a high-level controller invokes robot operations. A robot-specific driver implements that interface
for one declared robot configuration by translating each operation into
simulator or controller commands. Manually implementing this driver can delay
deployment for each new robot and execution route. AutoAdapter 1.0 showed that
an LLM could generate such a driver from machine-readable robot descriptions:
across eight simulated robots, it produced structurally validated, smoke-tested
drivers at US\$\(2.98 \pm 0.84\) and \(7.8 \pm 1.6\) minutes per robot. Yet all seven
evaluated models could use the same fixed capability interface backed by the same
fixed and validated driver, while only three generated a driver that passed
validation.

Auto-Adapter 2.0 asks whether an LLM can also design the reusable robot
capability interface and its capability-level pass criteria. Given public robot
facts and at least twenty tasks with documented pass conditions drawn from
public sources, an LLM defines five to ten reusable capabilities and
source-grounded capability-level pass criteria. It then generates a
robot-specific driver under either the skeleton-assisted or from-scratch
condition. An implementation-blind process audits and compiles the criteria
into private executable validation cases. A separate evaluation program, the
\emph{Harness}, owns the private cases, trusted-state measurements, and final
verdicts; its structured failure reports support bounded \emph{Repair}.

The evaluation comprises three experiments.
\textbf{Experiment 1---LLM backbone comparison.} We compare LLM backbones
when \textbf{synthesising} a robot-specific driver that implements a reusable
robot capability interface, either with access to the trusted skeleton or from
scratch, and when \textbf{using} the same fixed capability interface backed by the
same fixed and validated robot-specific driver through the same
high-level-controller implementation to complete matched robot tasks.

\textbf{Experiment 2---Auto-Adapter framework analysis.} We analyse three
components of the framework.
\textbf{(a) Task-grounded capability design.} We test whether an LLM can
derive reusable capabilities from at least twenty source-backed tasks.
\textbf{(b) Capability-level pass-criteria design.} We test whether
source-grounded capability-level pass criteria can be generated without human
predefinition.
\textbf{(c) Continued Evolution.} We test whether reviewed evidence from
completed runs improves robot-software synthesis quality in matched later runs
relative to the same condition without that Experience.

\textbf{Experiment 3---Cross-morphology analysis.} We hold the LLM backbone,
high-level-controller implementation, Auto-Adapter configuration, generation
condition, evaluation protocol, and resource budget fixed while comparing the
synthesis of robot-specific drivers that implement low-level motion-control
capabilities across \textbf{different robot morphologies}.

Within the evaluated scope, the thesis makes three scientific contributions:
\vspace{-.65\baselineskip}
\begin{enumerate}[leftmargin=*,labelsep=.8em,nosep]

  \item AutoAdapter-Bench separates robot-specific driver synthesis from
  capability-interface use. It evaluates the same LLM backbones in separate tracks
  and treats the two outcomes as different evidence categories, without
  assuming that they are statistically independent.

  \item Auto-Adapter makes capability and pass-criteria design explicit
  components of robot-software synthesis. The LLM derives capabilities from
  source-backed tasks and pass criteria from reviewed task-level standards. An
  implementation-blind process audits and compiles the criteria, while the
  independent Harness issues the final verdicts; Repair remains separate from
  later-run Evolution. A generated or successfully compiled criterion is not
  treated as reliable without the declared validation evidence.

  \item A controlled cross-morphology analysis studies robot-specific driver
  synthesis for low-level motion-control capabilities across the declared robot
  cohort. It compares validation outcomes, failure patterns, and resource use
  under matched conditions, and reports the observed differences as
  associations rather than causal morphology effects.

\end{enumerate}

Within the declared Direct-MuJoCo scope, the thesis also makes three bounded,
industry-relevant contributions:
\vspace{-.65\baselineskip}
\begin{enumerate}[leftmargin=*,labelsep=.8em,nosep]

  \item Traceability links reviewed task-level standards to
  model-authored capability-level pass criteria, independent compilation, and
  Harness verdicts for the declared tasks and validation cases.

  \item A repeatable robot-integration package supports scoped
  reuse. It records the robot assets, control facts, source-backed
  tasks, validation inputs, robot capability interface, and robot-specific driver needed
  to reproduce the declared integration.

  \item Comparable evidence supports failure diagnosis.
  AutoAdapter-Bench records driver synthesis and capability-interface use
  separately, together with the LLM backbone, robot configuration, generation
  condition, outcomes, failure patterns, resource use, and per-trial evidence
  under matched conditions.

\end{enumerate}

\end{abstract}
